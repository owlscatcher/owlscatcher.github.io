Когда мы настраиваем изолированную сеть при помощи Mikrotik, в сети которого устройства не будут иметь доступа до внешней сети,
хотелось бы сихронизировать время всех устройств с каким-то эталоном. В этой заметке я не буду рассматривать стоечные GPS
NTP-серверы, которые стоят по 2.000-3.000 долларов/евро. Вместо этого мы настроим свой NTP-сервер на Mikrotik, при этом немного
поколхозим, чтобы при перезагрузке мы не сильно съезжали по времени.

## Базовая настройка

Сначала нам стоит выставить руками системное время Mikrotik, которое по сути и будет раздаваться в локальную сеть.
Будем работать через терминал, чтобы не искать нужные кнопки в WinBox:

Для начала узнаем время на устройстве и тайм-зону:

```shell
/system clock print

# =>
#                   time: 10:26:10
#                   date: 2025-04-11
#   time-zone-autodetect: no
#         time-zone-name: Europe/Samara
#             gmt-offset: +04:00
#             dst-active: no
```

Выставим нужную дату, время и таймзону (время можно посмотреть на любом ресурсе в интернете):

```shell
/system clock set date=apr/01/2025 time=16:30:00 time-zone-name=Europe/Samara
```

Далее нам требуется отключить NTP-client, чтобы наш маршрутизатор не лез никуда за временем, так как мы не используем ни внешних устройств, ни внешних сервисов:

```shell
/system ntp client set enabled=no
```

Проверим:

```shell
/system ntp client print

# => enabled: no
```

Включим NTP-сервер и сконфигурируем его:

```shell
/system ntp server set enabled=yes broadcast=no multicast=yes manycast=yes
```

{{< alert "note" >}}
Обычно, когда настраивают локальный NTP-сервер, клиенты которого будут явно указывать хост NTP-сервера `multicast` и `manycast`
выставляют как `no`, но у меня не подхватывали машины адекватно данные с NTP и я оставил `multicast` и `manycast` как `yes`, а вот `broadcast`
я отключил.
{{</ alert >}}
